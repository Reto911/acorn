# 本人历史源码查看与审查行号定位审核记录

对应[设计 v1](../12-submission-source-design.md)。本记录保存接口取舍及用户确认，不登记功能实施或验收结果。

## 1. 讨论与决定

| 问题                           | 说明与决定                                                                                                                                                                                                                                                                                          |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 是否单独提供源码接口           | 源码可合并进单条提交详情，但会随状态轮询重复传输。独立接口增加一个读取流程，便于每次打开结果页只获取一次源码。现有详情数据库查询已经读取 source，拆分主要减少 HTTP 重复传输，不意味着现有详情查询不再读取源码。用户最终选择保留独立 GET /api/v1/submissions/{id}/source；详情及列表不增加源码字段。 |
| X-Acorn-User-Id 的作用         | 沿用既有页面预期身份校验：真实身份由 Cookie 对应的 Session 确定，请求头用于阻止共享 Cookie 的标签页在账号变化后继续按旧页面身份操作；不赋予身份或权限。                                                                                                                                             |
| Cache-Control: no-store 的作用 | 沿用既有个人接口的 HTTP 缓存策略，要求缓存不保存或复用私有响应。该策略不影响数据库持久化及页面内存展示，权限仍由会话与 SQL 归属条件保证。                                                                                                                                                           |

## 2. 最终确认

用户在明确保留独立源码接口后表示没有其他意见，批准设计 v1，并要求提交计划。后续开发按设计中的 SC01–SC04 及 SV01–SV05 执行。
