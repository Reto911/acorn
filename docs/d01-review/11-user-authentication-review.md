# 用户注册、登录与会话审核记录

对应[设计](../11-user-authentication-design.md)。本记录保存范围与参数决定，不表示功能已经实施。

## 1. 已确认决定

| 编号 | 决定                                                                                                                         |
| ---- | ---------------------------------------------------------------------------------------------------------------------------- |
| R01  | 用户保存到 MySQL，Session 放在后端内存，不引入外置会话服务                                                                   |
| R02  | 所有用户功能一致，提交及审查仅本人可见、可操作                                                                               |
| R03  | 全新部署，不设计向下兼容、迁移或热修复；预置用户在 seed-user 中提供可用测试密码                                              |
| R04  | 保留现有 role、status 字段供以后使用，撤回草案 v1 删除两列及升级结构版本的建议                                               |
| R05  | 未登录用户点击受保护功能时显示登录要求，优先使用现有对话框组件                                                               |
| R06  | 单用户容量满淘汰其旧会话，全局满淘汰全局旧会话，不返回容量不足错误                                                           |
| R07  | 暂不实现登录并发限制和登录失败次数限制                                                                                       |
| R08  | 按个人业余项目控制复杂度，优先复用现有实现；新增测试和检查必须事先明确告知用户                                               |
| R09  | Cookie Secure 通过 http.cookie_secure 配置，默认 false；按浏览器访问的外部协议选择，支持反向代理终止 HTTPS                   |
| R10  | 用户级与全局会话管理接受哈希索引的期望／均摊 O(1)，使用两套 LRU 顺序索引；过期数据清理允许 O(N)，具体决定见 D05              |
| R11  | 用户批准计划，并要求用户名、显示名和密码限制在前端同步执行；复用现有 Element Plus 表单校验，Unicode 相关规则补充自定义校验器 |

## 2. 精简建议与依据

- 现有 users 结构已具备所需字段，保留两列后沿用结构版本 4；这是复用现有结构，不建立兼容层。
- 请求大小复用 http.max_request_bytes，不增加独立 4 KiB 限额；移除原草案的认证限流器、失败计数表和密码计算名额。
- 全局 LRU 保存会话正文，按 user_id 索引的个人 LRU 只保存 token 顺序；访问和删除同步维护两套索引，个人计数和队首可直接取得。用户接受过期数据清理的 O(N) 成本，因此新建会话时从全局最旧端自动清理过期项，复用已有会话流程；本轮不另设定时器。此前禁止批量过期清理的限制由最终 D05 决定取代。
- 来源校验集中在一个入口；不增加额外 CSRF 请求头及 Referer 回退。基本 Cookie 属性和同源部署保留。
- 现有前端 [requestJson](../../web/src/api/http.ts)统一解析 JSON；退出建议使用 200 和 user=null，避免专门增加 204 空响应分支。204 本身也是标准状态码。
- 预期用户检查用于避免切换账号后旧页面误操作；保留简单字段比较，不建立跨标签页广播或通用会话协调系统。

## 3. 最终决策

D01–D05 已由用户确认，没有剩余待定选项。D01.3 在用户禁止空格后，通过后续答复确定最小长度为 8；其他细节按下表执行。决策确认不表示功能已经实现。

| 编号  | 项目               | 已确认结果                                                                                                                                  |
| ----- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| D01.1 | 用户名规则         | 接受原建议：3–32 个 ASCII 字母、数字或下划线；去首尾 ASCII 空白后统一小写，登录不区分大小写。                                               |
| D01.2 | 显示名规则         | 接受原建议：可选，不填默认等于用户名；去首尾空白后允许 1–64 个 Unicode 标量值，拒绝控制字符，支持中文，不要求唯一。                         |
| D01.3 | 密码规则           | 最小长度选择 8，最大 128 个 Unicode 标量值、最多 512 UTF-8 字节；禁止空格，实现按 Unicode 空白字符判定，直接拒绝而不裁剪；不要求字符组合。  |
| D02.1 | 续期与闲置时长     | 接受有效认证请求滑动续期，连续 24 小时无此类请求才过期；结果及健康轮询也算活动。续期同时更新活动时间、两套 LRU 顺序和浏览器 Cookie 有效期。 |
| D02.2 | 会话容量           | 接受每用户默认 10 条、全局默认 10000 条，均作为启动配置；按缓存条目计数，个人优先、全局随后按 LRU 淘汰。                                    |
| D02.3 | Cookie 生命周期    | 改为 24 小时持久 Cookie，Max-Age=86400；普通有效认证请求同步重设有效期，关闭浏览器不主动清除 Cookie。                                       |
| D03   | 注册后是否自动登录 | 接受注册后手动登录；注册成功返回 201 和公共用户，前端转回登录表单。                                                                         |
| D04   | 健康接口和页面     | 接受要求登录，全部用户均可访问，不引入角色。                                                                                                |
| D05   | 复杂度及过期清理   | 接受常规哈希表的期望／均摊 O(1)，不要求单次操作最坏 O(1)；过期数据清理可为 O(N)，允许自动清理或定时扫描。本轮采用新建会话时自动清理。       |

原密码下限 15 参考无多因素认证场景的 [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)；用户选择 8，以降低个人项目的使用门槛。字符计数规则见[设计第 3.1 节](../11-user-authentication-design.md#31-users-与全新初始化)，续期及清理机制见[设计第 4 节](../11-user-authentication-design.md#4-session-与-http-请求边界)。预置测试密码沿用设计中的默认凭据。
