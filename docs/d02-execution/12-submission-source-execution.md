# 本人历史源码查看与审查行号定位实施记录

对应[设计 v1](../12-submission-source-design.md)及[审核记录](../d01-review/12-submission-source-review.md)。任务沿用 SC01–SC04，验收沿用 SV01–SV05。

## 1. 当前状态与本轮范围

整体方案已获用户批准，保留独立源码接口。SC01.1–SC01.5 已完成并提交，后端源码接口及定向验收已交付；SC02.1–SC02.5 已完成实现及前端检查，SC03 的五项任务待实施，SC04 保留真实浏览器整体验收与使用说明交付职责。任务定义继续见[设计第 6 节](../12-submission-source-design.md#6-模块改动与实施步骤)。

SC01 交付 `GET /api/v1/submissions/{id}/source`，返回本人提交的原始源码，覆盖 SV01、SV02 的后端要求。接口沿用既有 Session、X-Acorn-User-Id、no-store 和 SQL 归属边界。数据库结构保持版本 4；SC02 提供只读编辑器与显示转换，源码查询和审查定位由后续 SC03 接通。

## 2. 开发清单

各项完成实现及相应检查后勾选，实际结果与遗留问题记录在[第 4 节](#4-实施记录)。

- [x] **SC01.1 定义源码读取类型与 HTTP DTO。** 在[提交类型](../../crates/backend/src/submissions.rs)新增小型 SubmissionSource，字段为 id、language_id、source，均为 String；source 表示数据库边界严格解码后的原文。在 [HTTP DTO](../../crates/backend/src/http/dto.rs)定义显式响应，只序列化 submission_id、language_id、source，并完成内部 id 的字段映射。更新 DTO 模块注释，保留详情和列表不返回源码的合同；新增 Rust 项提供 Rustdoc。无前置代码依赖。
- [x] **SC01.2 实现本人源码的最小投影查询。** 依赖 SC01.1；在[数据库提交模块](../../crates/backend/src/database/submissions.rs)新增 submission_source_for_user(user_id, id)，返回 Result<Option<SubmissionSource>>。同一参数化 SELECT 同时匹配 id 和 user_id，只读取 id、language_id、source；source 先按 Vec<u8> 读取，再经 String::from_utf8 严格解码，解码错误映射 Error::Data。通过现有 Database::observe 按普通读取观察 SQL 错误，返回自有数据并归还连接；不读取或解析判题和审查 JSON，不按业务状态限制读取，不重新检查当前源码接纳上限。
- [x] **SC01.3 接入受保护的源码 HTTP 路由。** 依赖 SC01.1、SC01.2；在 [HTTP 路由](../../crates/backend/src/http/mod.rs)的 personal 组注册 GET，处理器从 AuthenticatedUser 取得归属，按已有详情处理器解析并规范化 UUID，再调用本人源码查询。成功返回三字段 JSON；空结果使用现有 404 SubmissionNotFound，路径错误为 400 InvalidRequest，数据库或解码错误使用现有 500 InternalError。Session、预期账号及 no-store 继续由公共认证边界处理，避免重复实现校验或新增错误码。
- [x] **SC01.4 完成原文与权限的定向回归。** 依赖 SC01.2、SC01.3；按[第 3.1 节](#31-覆盖与复用入口)扩展现有认证测试，必要时增加一个源码读取的 HTTP／MySQL 用例，覆盖原文、排队与终态可读、本人隔离、认证先于参数解析、no-store 及严格解码失败。详情和列表不含源码的断言继续保留；新增或扩展检查前先告知用户覆盖内容与必要性。
- [x] **SC01.5 完成检查与后端交付说明。** 依赖 SC01.1–SC01.4；执行[第 3.2 节](#32-执行命令与环境)的必要检查，记录实际结果和未通过项。更新[后端 API 说明](../../crates/backend/README.md#http-api)的路由及携带 Cookie／预期账号的读取示例，将[后端设计](../03-backend-design.md#5-http-接口)与[用户设计](../11-user-authentication-design.md#52-对现有业务的改动)中的计划性描述同步为已接入的接口合同；[前端依赖表](../05-frontend-design.md#61-首版接口覆盖与缺口)注明后端接口已提供、页面仍按 SC02–SC03 接入。保持设计中的 SC01–SC04 标识及未实施任务的状态准确。

### 2.2 SC02 只读编辑器与行段定位

SC02 提供供结果页复用的展示和定位能力，沿用[设计第 4 节](../12-submission-source-design.md#4-源码原文与定位行号)的 LF 行号合同。

- [x] **SC02.1 实现只读显示文本转换。** 在 `web/src/utils/sourcePresentation.ts` 增加小型纯函数，从原始字符串生成显示文本及是否需要回车提示的标记。仅将不属于 CRLF 的单独 CR 替换为 `␍`，其余字符及 LF 分行位置保持不变；输入原文由调用方独立保留。该步骤可独立实施，转换结果只用于只读模型。
- [x] **SC02.2 扩展 CodeEditor 的只读用途。** 在[编辑器包装](../../web/src/components/CodeEditor.vue)增加默认关闭的只读属性及清晰的用途标签，保留现有 Monaco、语言注册和 480 px 容器。只读用途固定语言，支持高亮、行号、查找和选择，长行水平滚动；不注册向外更新源码的内容监听。编辑用途继续使用现有 v-model 与双语言模型，保持[答题组件](../../web/src/components/SubmissionEditor.vue)的编辑和草稿行为。更新仅在答题页加载的旧注释，该步骤不依赖后端运行。
- [x] **SC02.3 提供显式定位与清除入口。** 依赖 SC02.2；由 CodeEditor 暴露类似 revealLines(lineStart, lineEnd) 和 clearHighlight() 的小型方法，供 SC03 调用。按包含首尾的范围添加整行背景及行号旁标识，显示目标行段并聚焦；每次调用均执行定位，同一范围重复调用也生效，切换范围替换旧高亮。页面滚动、所选疑点和“已定位”文案由 SC03 负责。
- [x] **SC02.4 完成模型与定位资源清理。** 随 SC02.2–SC02.3 实施，将装饰、内容监听、编辑器及自建模型纳入现有卸载流程。清除定位只移除高亮，不改变源码；更换模型不保留旧模型的定位，卸载时释放相关资源。只读视图不把 Monaco 规范化后的文本回写原文；源码请求、账号和路由清理由 SC03 管理。
- [x] **SC02.5 完成定向检查并记录交付范围。** 依赖 SC02.1–SC02.4；按[第 3.3 节](#33-sc02sc03-定向验证安排)补充少量显示转换用例，复用现有草稿回归，执行前端已有检查。记录实际结果及未验证范围；Node／SSR 结果不作为 Monaco 滚动、焦点或只读交互通过的依据，真实页面验证在 SC03 接线后由 SC04 汇总。

### 2.3 SC03 源码查询与结果页联动

SC03 使用已交付的 SC01 接口及 SC02 编辑器能力，按[设计第 5 节](../12-submission-source-design.md#5-结果页与交互)完成页面接线。

- [ ] **SC03.1 接入源码 DTO 与 API 方法。** 在[前端类型](../../web/src/api/types.ts)定义三字段 SubmissionSource，language_id 使用既有 LanguageId；更新查询不返回源码的旧模块注释。在 [API 入口](../../web/src/api/index.ts)增加 getSubmissionSource，编码提交 ID，传递 AbortSignal 和调用方冻结的 expectedUserId，复用 requestJson 和既有错误反馈。保留接口返回的原始字符串，日志仅包含请求元数据，不输出源码。依赖 SC01，不依赖编辑器。
- [ ] **SC03.2 增加独立源码区域并接入结果页。** 依赖 SC03.1、SC02.1–SC02.2；新增 `web/src/components/SubmissionSource.vue`，在[结果页](../../web/src/pages/ResultPage.vue)首次取得提交详情后，以 submission_id 为 key 挂载在审查区域之后、固定题面之前。复用 useQuery，以提交 ID 为唯一查询源且不设置周期刷新；保留原文，使用响应语言和 SC02 的显示文本，异步加载只读 CodeEditor。源码加载和错误在区域内展示，“重试读取源码”仅手动重发该 GET；首次详情尚未成功（包括查询失败）时不发源码请求，轮询、刷新结果及重审不改变源码区域的 key 或重建模型。
- [ ] **SC03.3 接通审查行号按钮与源码定位。** 依赖 SC03.2、SC02.3；在[审查组件](../../web/src/components/SubmissionReview.vue)增加包含 review_id 和闭区间的类型化定位事件，单行与多行按钮可通过键盘操作。ResultPage 只保留最后一次选择，每次点击产生新的定位动作；接口成功且异步编辑器引用就绪后，调用 SC02 的显式入口，滚动页面、聚焦并显示“已定位”范围。源码加载中或读取失败时保留最后选择，不自动发请求；手动重试成功后再定位。无有效 finding 时不提供入口，不默认选中或抢焦点。
- [ ] **SC03.4 接通身份、路由及审查变化的清理。** 随 SC03.2–SC03.3 实施；页面个人请求使用同一已确认身份快照，沿用 auth.handleError，身份代次变化时同步停止源码查询并清空原文和选择。切换提交卸载旧源码区域，忽略取消后的迟到结果，复用 App 的私有页面重建及 useQuery 的释放机制。review_id 改变或没有有效审查结果时清除高亮，同一审查的普通轮询保留选择；重新审查不重新读取不可变源码。源码与定位状态只保存在本页内存。
- [ ] **SC03.5 完成定向回归及交付记录。** 依赖 SC03.1–SC03.4；扩展已有 API 与审查组件检查，核对预期账号头、原文返回、按钮文案及文本转义，复用已有查询和身份生命周期测试。执行前端已有检查并记录结果；将真实点击、滚动、焦点、只读及账号切换的浏览器验证明确交给 SC04，不以 Node／SSR 结果代替。页面功能和使用说明的最终验收按设计 SC04 收口。

### 2.4 依赖与阶段交付

SC02.1 与 SC02.2 可以分别推进，SC02.3 依赖 SC02.2，SC02.4 随对应实现完成，SC02.5 汇总编辑器及纯逻辑的检查结果。SC03.1 可与 SC02 并行，SC03.2 在 API 和只读能力具备后接入，随后完成定位与清理，再执行 SC03.5。

## 3. 定向验证与交付检查

### 3.1 覆盖与复用入口

优先使用 [authentication 测试模块](../../crates/backend/tests/cases/authentication.rs)及现有独立 MySQL／HTTP 夹具，不另建测试框架。用已有公共边界证明新路由被正确接入，避免复制会话和 Cookie 的完整测试矩阵。

| 位置                                           | 覆盖内容                                                                                                                                                                    | 必要性                                                  |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 扩展 authentication_routes_and_request_guards  | 将源码路径加入匿名 401 与错误预期账号 409 的现有场景；使用非法 UUID 确认身份检查优先，合法会话及匹配账号下该路径返回 400；补充缺失预期账号头的拒绝断言                      | 验证新路由没有绕过 personal 边界，沿用已批准的错误顺序  |
| 扩展 personal_submission_ownership_and_queries | 两账号分别读取本人源码成功，读取他人和不存在的源码返回相同 404；检查响应仅有约定三字段，详情和列表仍无源码                                                                  | 验证同一 SQL 限定归属，防止新增响应泄漏完整内部提交对象 |
| 新增必要的源码读取 HTTP／MySQL 场景            | 使用同时包含中文、制表符、空行、LF、CRLF、单独 CR 及末尾换行的源码，比较响应字符串重新编码后的字节与提交原文；同一提交在 queued 和通过既有 save_terminal 保存终态后均可读取 | 覆盖原文不被裁剪或转换，以及读取不依赖机器判题结束      |
| 在源码读取场景中补充严格解码检查               | 仅在独立测试库中将该记录的 source 改为非 UTF-8 字节，再读取并确认返回 500 InternalError，不返回有损替换的字符串                                                             | 覆盖新增字节到字符串转换的明确失败合同                  |

现有 request 辅助函数会检查 no-store。通过 call 辅助函数取得的源码成功及 404 响应须显式检查该头；500 场景同样检查，确保错误也沿用公共缓存策略。无需用真实 Worker 执行测试源码，或调用 Kafka、Isolate 和外部模型来证明只读接口合同。

上述场景可放在同一 authentication 模块，由已有 workflow 过滤命令运行，不再为同一合同建立重复的数据库测试集。既有[数据库二进制类型测试](../../crates/backend/tests/database.rs)仍作为 LONGBLOB 按字节读取的基础，不因新增接口而改写 SQLx 类型规则。

### 3.4 前端命令与真实浏览器验收边界

SC02、SC03 实施时在 web 目录沿用设计已列出的 pnpm format:check、lint、typecheck、build、test 命令。各阶段相关检查通过后保留结果，不因进入下一任务重复已通过且未受新改动影响的专项检查；纯规划阶段不运行这些业务检查。

SC04 复用已有桌面浏览器环境和受控审查结果，按以下有限场景核对：

1. 本人历史源码与当前草稿不同，页面仍展示该次提交的只读内容；C/Python 可查找、选择及水平滚动，原答题编辑、语言切换和草稿仍工作。
2. 单行、多行及重复点击均正确定位；LF、CRLF、单独 CR 和尾换行符合物理行规则，切换疑点替换高亮，定位有文字状态并能获取键盘焦点。
3. 源码延迟或失败时只保留最后选择，手动重试后应用；详情轮询、刷新和重审不增加源码 GET 或重建模型，新审查清除旧高亮。
4. 源码请求在途时切换提交或账号，旧文本、待定位和迟到响应不再展示；离页释放模型、监听和装饰。

这些检查在已有结果页执行，不为单独验证 SC02 增加临时产品入口。真实浏览器操作和资源释放结果按实际证据记录，不新增外部模型调用或重复完整判题矩阵。
