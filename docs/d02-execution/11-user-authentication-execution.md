#### 3.1.2 实现要点与后续衔接

输入规则以[设计第 3.1 节](../11-user-authentication-design.md#31-users-与全新初始化)为准，由 auth 提供单一实现，注册与登录复用：

- 用户名只去首尾 ASCII 空白，校验 3–32 个 ASCII 字母、数字或下划线后转小写；不能用会裁剪 Unicode 空白的通用 trim 替代。
- 显示名省略时采用规范化用户名；显式值去首尾空白后按 Unicode 标量计数，接受 1–64 个且拒绝控制字符。显式空串按无效输入处理。
- 密码按 chars().count() 限制为 8–128 个标量、UTF-8 不超过 512 字节，按 char::is_whitespace 拒绝空白；原值用于哈希和验证，不裁剪、截断或改写。
- 注册、登录输入都拒绝未定义字段；不从客户端接收 user_id、role 或 status。密码输入及含哈希的凭据类型不派生会暴露其内容的 Debug 或 Serialize，错误和日志不包含这些值。

数据库读取返回公共用户字段及密码哈希的自有值，函数返回时归还连接，不向 auth 返回连接、事务或借用数据库行。创建仅接受已校验的用户名、显示名和已生成哈希；数据库负责 ID、创建时间及固定保留字段，使用参数绑定和现有 SQLx 检查式解码，不增表或改结构版本。

复用 Database::observe、mysql_error_number 和 now_ms：用户名唯一键冲突须在 observe 观察结果之前转换为 UsernameTaken，不能先按关键写入故障通知后再转换。读取沿用普通读错误边界，其他创建数据库错误沿用关键写入错误边界；不把所有操作的 1062 统一改成用户名重复，也不增加注册前查重流程。

密码能力只负责生成和验证 PHC，复用成熟 Argon2 实现和所需的安全随机能力，补充必要依赖并锁定版本。校验不匹配与损坏的存储哈希、随机源或后台任务失败保持区别：密码不匹配用于 InvalidCredentials，执行或存储数据错误保留内部错误上下文，不伪装成成功或普通密码错误。

U02.4 组装注册与登录流程时遵守两个顺序：注册先校验、在阻塞任务中哈希、再插入；登录先查出凭据并释放连接、再在阻塞任务中验证，最后创建 Session。不存在的用户名和错误密码在该接口统一为 InvalidCredentials。U01 不接入认证路由、AppState、Session、Cookie、个人提交隔离或前端表单；test_user.user_id 及启动用户检查按 U03.4 移除，因此 U01 完成不代表空用户表已可启动。

### 3.2 U02 内存会话与认证接口

依赖 U01 的用户信息和密码能力；合同见[设计第 4 节](../11-user-authentication-design.md#4-session-与-http-请求边界)及[认证接口](../11-user-authentication-design.md#51-认证接口)。主要入口为 auth、HTTP、AppState 和配置加载器。

- [x] U02.1 建立全局 LRU 和按用户索引的个人 LRU，以一把短锁保护并接入 AppState；实现安全随机 token、查找及同步删除两套索引的共用流程。依赖 D05；会话正文只存一份，用户索引仅保存 token 顺序，容器长度直接提供计数，用户无会话时删除其索引；锁不跨数据库、密码计算或网络等待。

- [x] U02.4 接入 register、login、me、logout 四个接口。依赖 U01、U02.1–U02.3、D03；响应、状态码和业务错误沿用设计，登录成功新建会话、失败保留原会话，退出幂等且返回现有前端可解析的 JSON，me 可返回 user=null。

#### 3.2.2 会话与请求处理边界

会话实现遵守[设计第 4.1 节](../11-user-authentication-design.md#41-会话内容和生命周期)：

- 全局及个人 LRU 均须支持按键定位、移动、删除及取最旧项，容器维护长度；由业务显式淘汰，保证共用删除入口同步维护索引并移除空用户索引。
- 一把短同步锁保护两套索引，锁内只做缓存操作和单调时间判断。token 生成、数据库访问、密码计算及 HTTP 等待在锁外进行；密码验证成功后才进入新会话流程。
- 认证有效后以原 token 更新最后活动时间和两套顺序，并在响应重设 Max-Age=86400。过期访问只能删除；会话正文和 token 不进入数据库、日志、URL 或 Web Storage。
- 登录先按全局旧端清理全部过期项，再替换请求携带的旧会话及处理容量；登录失败不删除旧会话。普通访问及淘汰保持期望／均摊 O(1)，清理 K 个过期项为 O(K)。

Cookie 使用 acorn_session，Secure 开启时改用 __Host-acorn_session 并附加 Secure；两者均为 Path=/、HttpOnly、SameSite=Lax，不含 Domain。设置与续期使用 86400 秒，退出以相同名称及属性清零。public_origin 表示浏览器访问的外部 HTTP(S) Origin，配置格式及代理示例随 U02.3 同步设计；HTTPS 代理连接 HTTP 后端时仍可开启 Secure。

认证接口复用 U01 的实际调用顺序：注册 validate → hash_password → create_user → AuthResponse；登录 validate → user_by_username → 释放连接 → verify_password → 创建会话。用户名不存在及密码不匹配统一为 401 InvalidCredentials，损坏哈希及计算失败沿用内部错误。所有 401 附带 WWW-Authenticate: Session realm="acorn"。

写请求的 Origin 校验覆盖注册、登录、退出、创建提交及手动审查；缺失、null 或不精确匹配均拒绝。个人提交查询、创建、审查及有效会话退出比较 X-Acorn-User-Id 与已验证身份；auth/me 不要求该头。健康接口要求登录，所有账号功能一致。认证及个人数据响应统一 no-store，继续复用 JSON 拒绝转换、DefaultBodyLimit 和不记录请求正文的日志方式。

U02 为后续业务提供请求内不可变的 AuthenticatedUser。提交归属、幂等查重、历史／详情过滤及手动审查的用户条件仍按 U03 接入；U02 的登录门控完成不能作为多用户隔离验收。test_user 配置和启动用户检查保留至 U03.4，前端账号状态和表单按 U04 实施。

#### 3.3.2 身份传播与内部职责

创建链路须同时改完四个归属使用位置：CreationService::create_owned 的 submission_by_key 预查、创建事务内初次 by_key、INSERT submissions.user_id，以及 1062 回滚后新短事务中的 by_key 重读。Database::submission_by_key 增加 user_id 参数，复用已经接受 user_id 的私有 by_key helper；既有内容比较、固定版本装配、排队重新交接和容量规则保持一致。传入独立任务的是用户 ID，不是 Cookie 或 Session 句柄；退出、过期、账号切换和 HTTP 取消均不改写已接纳操作的归属。

历史 SQL 用显式用户参数替换配置测试身份；详情在同一条 SQL 同时过滤提交 ID 与用户 ID。无用户条件的 submission 入口保留给可信内部处理，并以命名和 Rustdoc 与 HTTP 读取区分；不先读取其他用户的完整结果再由 handler 或页面隐藏。

手动审查的传播顺序为 HTTP 身份 → start_manual → ManualRequest.user_id → 独立 admissions 任务 → manual_owned → admit_review。现有 Database::start_review 包装入口也须增加必需的用户参数，避免漏传。锁行条件改为 WHERE id = ? AND user_id = ? FOR UPDATE；未命中走 NotFound，命中后才判断机器终态、读取已有审查、复用 PENDING、比较 expected_review_id 或更新意见。保留既有短事务、接纳名额及独立操作的生命周期。

内部 Scheduler／Kafka、自动审查、完成写入及启动恢复继续按提交 ID 工作。submission_state、judging_context、queued_task、judging_recovery、机器状态及终态更新、review_input、finish_review 和 interrupt_pending_reviews 不附加当前浏览器的用户过滤，也不向 Worker 或模型传入 Session。删除 test_user 后，启动的结构检查、旧 PENDING 中断及全用户任务恢复顺序不变。

既有 Tower 夹具通过真实登录取得 Cookie，并为原业务调用补齐 Origin 和预期用户头；网络夹具通过登录交换获取 Cookie。健康数据库故障用例在登录后移除用户并锁表，验证认证及健康查询不逐请求读取账号。新增认证 HTTP 检查覆盖注册不自动登录、重名、登录失败保留和成功替换会话、匿名身份、退出及重复退出、Cookie 续期与 Secure、两级容量淘汰、401／403／409 及拒绝请求不创建提交。
