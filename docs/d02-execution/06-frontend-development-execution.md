### 5.2 F02：API 与客户端生命周期

已在 `web/src/api/` 定义题目、语言限额、分页、创建、历史和提交详情的 HTTP DTO。详情通过状态与 verdict 区分运行中、AC、CE、用例失败和执行失败，保留 `null`、省略资源字段与显式零值。六个既有接口均有调用函数，只发送契约允许的字段；创建函数接受调用方提供的键和快照，并验证 `200` / `202` 的提交身份与状态后才确认成功。

共用 `fetch` 请求函数覆盖响应体读取在内的 10 秒超时、调用方取消、HTTP 错误提取、网络错误和非 JSON 响应，单次调用不会自动重试。`useQuery` 在页面身份或查询参数变化及作用域销毁时取消旧请求，忽略迟到响应；手动刷新失败保留上次成功数据。共用提示组件分别提供加载、空数据和中文错误、英文辅助信息及手动重试入口；HTTP 查询失败与持久化业务 `failed` 分开处理。

`useSubmissionRequest` 在发送前冻结题号、语言、原始源码和一次生成的 UUID，同时保存到内存与 `sessionStorage` 的 `acorn:pending-submission:v1`。成功或明确业务拒绝清除快照；`QueueFull`（含已有 ID）、`BackendStopping`、网络/解析/超时、其他 5xx 和未知拒绝保留原请求。重新进入答题页只恢复提示，手动重试始终使用原键原内容；在途禁止新建、重复重试和放弃。确认放弃清除请求快照而不触碰草稿，存储不可用或写入失败明确提示恢复限制。成功重试导航结果路由，离页或改变页面身份后不会迟到跳转。

浏览器公共日志记录请求操作、路径、状态码、错误码、已知提交 ID、耗时和状态变化；轮询日志仅为 debug，生产默认关闭。Vue、浏览器 `error` 与 `unhandledrejection` 接入同一去重入口并显示可操作提示。日志不传入源码、请求正文、幂等键和程序输出；异常只保留类型及调用栈帧，解析错误和任意异常消息可能包含正文，因此不直接输出。

### 5.10 F08/H03：HTTP 快照与生命周期

已在[HTTP 路由](../../crates/backend/src/http/mod.rs)增加 `GET /api/v1/health`，共享已有创建服务、Scheduler 及 Health 句柄。请求只读取本地状态及最近观测缓存，不执行 SQL 或 Worker RPC；[响应 DTO](../../crates/backend/src/http/dto.rs)显式转换约定的状态和错误码，保留固定字段及 `null`，分别输出后端 UTC 组装时间和各项探测完成时间。组件失败、过期、容量满或停止接纳时仍返回 `200`，组装错误沿用 `500 InternalError`；健康 GET 的成功及组装错误响应均附带 `Cache-Control: no-store`，不公开内部地址、数据库路径或原始诊断。

[程序入口](../../crates/backend/src/main.rs)在 Scheduler 组装后启动唯一采集任务，监督其返回结果与 JoinError。采集任务异常结束只记录错误，判题和 HTTP 继续运行，不重建采集；严重数据库错误仍由既有通知触发故障退出。入口统一在同一个 select 循环中等待 Scheduler、HTTP、健康任务及停止信号，Scheduler 正常结束后继续监督 HTTP 收尾，避免提前退出监督或再次轮询已完成的任务。

正常停机先停止新提交及分派，等待短创建操作和在途跟踪，期间健康采集及 HTTP 查询继续可用；HTTP 结束后通知健康采集停止并等待其结束，最后由原有流程关闭数据库。业务故障时立即通知采集停止，在原有业务收尾后等待采集结束。两条路径都可中断尚未完成的探测，不等待整个健康预算，也不取消 Worker Job 或追加 ACK。
