# 本人历史源码查看与审查行号定位设计

版本：v1。本文定义本人历史提交源码的只读查询、结果页展示和审查疑点定位方案，以及接口、行号、生命周期、实施步骤及验收要求。方案确认见[审核记录](d01-review/12-submission-source-review.md)。既有合同见[后端设计](03-backend-design.md)、[前端设计](05-frontend-design.md)、[LLM 审查设计](08-llm-code-review-design.md)和[用户设计](11-user-authentication-design.md)。

## 1. 需求与范围

用户从个人历史或结果链接打开一次提交时，需要看到当时实际提交的代码，并根据审查意见核对对应源码，而不是依赖当前浏览器中可能已经修改的草稿。

本轮提供：

- 在现有结果页查看该次提交的完整源码，支持固定语言的语法高亮、行号、查找和文本选择，源码只读。
- 在每条有效审查疑点中点击行号，滚动到源码对应行段并高亮闭区间。
- 源码读取沿用本人归属校验、预期账号校验和账号变化时的私有数据清理。
- 无审查、审查失败或机器判题尚未结束时，同样可以查看已经持久化的本人源码。

范围限于查看与定位。将历史源码回填为答题草稿、重新提交、下载文件、源码差异比较和审查历史保留另行定义；现有“返回答题”继续打开最新题面与当前草稿。

## 2. 项目基础与方案选择

| 现有基础                                                             | 对本轮的作用                                                 |
| -------------------------------------------------------------------- | ------------------------------------------------------------ |
| submissions.source 保存原始 UTF-8 字节，创建时不裁剪或调整换行       | 直接读取既有记录，无需增加源码副本或修改数据库结构版本       |
| 个人详情通过同一 SQL 匹配提交 id 与认证 user_id                      | 源码接口沿用相同的归属边界                                   |
| 详情 DTO 不返回源码，运行中或审查 PENDING 时每秒查询详情             | 源码独立读取，避免轮询反复传输不变内容                       |
| review.result.findings 已有 line_start、line_end，后端按原始源码校验 | 直接使用现有意见定位，无需修改模型输出、Kafka 或 Worker 协议 |
| CodeEditor 已包装 Monaco、语言注册及模型销毁                         | 增加只读用途和行段定位，复用现有依赖                         |
| useQuery、useAuth 和私有页面已有取消及身份代次规则                   | 复用请求和清理流程，不增加全局缓存或新的身份机制             |

选择新增独立 `GET /api/v1/submissions/{id}/source`。若将 source 加入现有详情，接口数量较少，但每次状态轮询都要重复传输源码；当前默认源码上限为 65,536 字节，独立 GET 更适合其不可变特性。现有详情和列表继续使用原响应形状。

页面继续使用 Monaco：行号、查找、语言高亮及行段滚动已有组件基础。只读查看不接入包含草稿、保存快捷键和提交操作的 SubmissionEditor，而由独立源码区域组合查询和 CodeEditor。源码和审查证据均作为文本处理，不作为 HTML、模板或可执行内容加载。

## 3. HTTP 与数据库合同

### 3.1 请求与响应

```http
GET /api/v1/submissions/{id}/source
Cookie: acorn_session=<登录取得的 token>
X-Acorn-User-Id: 1
```

成功返回 `200 OK`、`Content-Type: application/json` 和 `Cache-Control: no-store`：

```json
{
  "submission_id": "7b5f28d3-51a4-463c-98a4-0a11815d8d46",
  "language_id": "python",
  "source": "a,b=map(int,input().split());print(a+b)\r\n"
}
```

| 字段          | 含义                                                               |
| ------------- | ------------------------------------------------------------------ |
| submission_id | 路径对应提交的规范 UUID                                            |
| language_id   | 该提交固定的 c 或 python，供只读查看选择语言                       |
| source        | 原始源码的 UTF-8 字符串；JSON 解码后重新编码的字节须与存储内容一致 |

不重复返回题面、题号、版本、状态、时间和审查意见，这些数据继续由已有详情提供。读取不要求 finished，不触发判题、审查或状态更新。

### 3.2 权限与错误

新路由加入现有 personal 路由组，会话及单个 X-Acorn-User-Id 的检查先于路径参数和数据库查询。GET 沿用现有个人读取规则，不增加写请求的 Origin 要求；成功和失败响应均沿用 no-store。

| 情况                                   | 响应                                          |
| -------------------------------------- | --------------------------------------------- |
| 本人已持久化的提交                     | 200，返回固定源码，与判题和审查状态无关       |
| 未登录、会话无效或过期                 | 401 AuthenticationRequired                    |
| 预期用户头缺失、无效、重复或与会话不符 | 409 SessionChanged                            |
| 提交 UUID 格式无效                     | 400 InvalidRequest                            |
| 不存在或属于其他用户                   | 相同的 404 SubmissionNotFound                 |
| 数据库读取或存储源码解码失败           | 500 InternalError，按现有读取错误合同记录原因 |

账号来自已认证会话，不接受查询参数指定归属。不因管理员字段或当前题目版本而扩大读取范围。

### 3.3 数据读取与编码

在 database/submissions 增加类似 submission_source_for_user(user_id, id) 的只读方法，使用绑定参数执行：

```sql
SELECT id, language_id, source
FROM submissions
WHERE id = ? AND user_id = ?
```

该最小投影无需解析机器终态或审查 JSON，不调用无归属条件的内部读取再事后过滤。使用普通读取和现有共享连接池，不另加事务、行锁或索引。

source 按 LONGBLOB 读取为字节，再严格转换为 UTF-8 字符串；沿用已有 Error::Data 和 HTTP 内部错误映射，不进行有损替换、截断、格式化或换行改写。已持久化数据服从创建时的源码预算，读取不重新套用当前部署的接纳上限。数据库结构保持版本 4。

## 4. 源码原文与定位行号

### 4.1 沿用既有审查规则

现有审查提示词和保存边界已约定：按原始源码中的 LF 物理行从 1 开始计数，CRLF 只产生一次分行，末尾 LF 不额外增加可定位空行；line_start 和 line_end 均包含在范围内。

| 原始字符串 | 可定位行数 | 说明                                           |
| ---------- | ---------- | ---------------------------------------------- |
| `a`        | 1          | 无末尾换行                                     |
| `a\n`      | 1          | 末尾换行不增加一行                             |
| `a\n\n`    | 2          | 中间的空行仍计入                               |
| `a\r\nb`   | 2          | CRLF 与 LF 的行号一致                          |
| `a\rb\nc`  | 2          | 单独 CR 不属于 LF 分行，a 与 b 仍在审查第 1 行 |

有效 finding 已由后端校验为 `1 <= line_start <= line_end <= 源码物理行数`。本轮不修改审查提示词、输出结构或保存校验，也不在浏览器重新解释疑点证据、猜测行号或裁剪无效范围。

### 4.2 Monaco 展示与原文分开

Monaco 会把单独 CR 也作为换行，直接用其默认模型行号定位可能与既有 LF 合同错位。源码区域保留接口返回的原始字符串，只为只读模型生成显示文本：将不属于 CRLF 的单独 CR 替换为可见符号 `␍`，LF 和 CRLF 保持原有分行位置。

仅在存在这种字符时显示提示“单独的回车字符以 ␍ 显示，行号按 LF 换行计算”。该转换不回写源码或草稿，不用于提交、审查或数据库写入。普通文本选择取得的是展示内容；接口始终提供完整原文。

Monaco 在末尾换行后显示的额外空行可以保留，它不属于后端允许的 finding 定位目标。语言固定取 source 响应的 language_id；视图不自动格式化或折行，长行在代码区内水平滚动，行段高亮不依赖列偏移。

只读用途不注册向外更新源码的内容监听，不把 Monaco 规范化后的模型文本赋回 API 原文。编辑用途保留既有双向绑定和草稿行为，两个用途共享模型创建与销毁的基本流程。

## 5. 结果页与交互

### 5.1 页面组合与加载

沿用 `/submissions/:submissionId`，页面顺序为提交信息、机器结果、代码审查、本次提交源码、固定版本题面。源码区域默认展开，代码区使用现有 480 px 高度，适用现有不小于 1024 CSS px 的桌面范围。

第一次成功取得该提交详情后，以 submission_id 为 key 挂载源码区域，立即发出一次独立 GET；Monaco 随该区域异步加载。详情尚未加载或已被归属检查拒绝时，不并行发起源码请求。

源码查询复用 useQuery，不设置周期刷新。成功快照只保存在本次页面内存中；状态轮询、手动
刷新结果和重新审查均不重新读取源码，也不重建同一提交的源码模型。真正离开页面或切换提交后，新的挂载重新读取。

读取失败时在源码区域显示 RequestFeedback 和“重试读取源码”，不影响已有机器结果及审查内容；重试仅发送源码 GET。失败不触发提交或审查 POST，也不自动反复重试。

### 5.2 疑点定位

每条有效 finding 保留类别、证据和可能的正常解释，将原行号文字改为可用键盘操作的“查看第 X–Y 行”按钮，单行显示“查看第 X 行”。

用户点击后：

1. 将当前 review_id 及该 finding 的闭区间记为本页选择，只保留一个选中行段。
2. 如果源码已就绪，滚动页面使代码区可见，在 Monaco 中显示目标行段，并将键盘焦点移到只读代码区。
3. 用整行背景和行号旁标识高亮 `[line_start, line_end]`，同时显示“已定位：第 X–Y 行”，让状态不限于颜色表达。
4. 再次点击相同行段仍执行定位；切换疑点时替换原高亮。

源码仍在加载时保留最后一次选择，加载完成后应用；多次点击只保留最后一条，不创建新请求。源码加载失败时保留所选疑点，用户点击源码重试并成功后再定位，不由行号按钮自动重复读取。

PASS 没有 finding，未审查、PENDING 和 FAILED 没有有效意见时，不显示定位入口；源码区仍可独立查看。不默认选中第一条疑点，也不在页面加载完成时自动抢焦点。

### 5.3 身份、路由与重新审查

源码 GET 冻结当前身份快照，发送相同的 expectedUserId，并复用 auth.handleError。身份代次变化时同步停止旧查询、清空原文与所选疑点；页面和模型随私有页面重建或卸载而释放。取消之后的成功或失败响应不得重新展示旧账号源码。

切换 submission_id 时卸载旧源码区域，取消请求并清空选择，不能把旧提交的文本或待定位范围用于新提交。

review_id 改变或当前快照不再包含有效审查意见时清除选择与高亮。同一 review_id 的普通轮询不清除高亮。重新审查只替换意见，源码不可变，因此不重新下载源码；收到新意见后由用户主动选择新的疑点。

沿用现有身份确认和恢复方式，不把源码保存到 localStorage、sessionStorage 或全局缓存，不新增跨标签页同步。前端和后端日志均不输出源码正文。

## 7. 最小验收与检查

新增或扩展测试前先说明覆盖内容与必要性。优先复用现有 authentication、database、API、useQuery 和 SubmissionReview 测试；只为新增的显示文本转换及尚无覆盖的定位联动补必要用例。

| 标识 | 验收内容                                                                                                                | 必要性                                           |
| ---- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| SV01 | 包含中文、制表符、空行、CRLF、单独 CR 和尾换行的源码，接口返回 UTF-8 字节与提交原文一致；一个排队场景及已有终态均可读取 | 验证原文而非当前草稿，以及读取不依赖判题完成     |
| SV02 | 本人成功，他人／不存在同为 404；匿名和预期账号不符沿用 401／409；响应 no-store；详情及列表继续不含源码                  | 验证新增敏感读取未绕过既有权限，轮询响应保持轻量 |
| SV03 | 单行、多行、LF／CRLF、末尾换行和单独 CR 的定位与第 4 节一致；重复点击、切换疑点和重审后清除高亮正确                     | 覆盖新增行号转换和交互的具体出错边界             |
| SV04 | 详情轮询与手动刷新不增加源码 GET；源码失败只局部提示，手动重试后完成待定位；源码不写浏览器存储                          | 验证一次读取与独立错误边界                       |
| SV05 | 源码请求在途时切换账号或提交，迟到响应不显示；只读视图不能修改文本，原答题编辑和草稿仍工作                              | 覆盖个人数据隔离及共享编辑器改动影响             |

后端复用现有测试夹具，不需要运行真实 Kafka、Worker 或外部模型来验证源码读取。真实浏览器使用本人已有提交和包含有效疑点的受控审查结果，核对滚动、整行高亮、键盘焦点、只读行为及桌面布局；Node／SSR 检查不代替这部分浏览器行为。
