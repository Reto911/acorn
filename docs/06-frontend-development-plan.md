# 前端开发计划

本文定义 F01–F08 的任务、接口依赖、实施顺序和验收要求；健康观测细分为 H01–H04，LLM 页面增量由[第 08 篇 L05–L06](08-llm-code-review-design.md#105-l05结果页轮询与历史筛选)定义。范围确认见[审核记录](d01-review/06-frontend-development-review.md)，完成状态与实际检查见[实施记录](d02-execution/06-frontend-development-execution.md#5-实施记录)。

## 1. 目标与依赖

依据[前端 GUI 设计](05-frontend-design.md)建设 Vue 3 + TypeScript + Monaco 的浏览器应用，首版交付题目列表、答题、提交结果、提交历史和本地草稿。先完成用户判题链路，再开展低优先级的健康观测。

GUI 仅面向视口宽度不小于 1024 CSS px 的桌面浏览器。移动端及更窄视口不在适配、测试和验收范围，后续任务不安排手机竖屏或窄屏布局检查；已有窄屏样式无需作为交付要求维护。

F01–F07 依赖 P01–P10 定义的题目、指定版本、提交创建、详情和历史接口，以及启动、停机与故障合同；复用五份源码样例进行浏览器验收。基础 GUI 使用现有 HTTP 契约，不要求修改 Proto、数据库结构或后端配置格式。后端实际交付范围见[实施记录](d02-execution/04-development-execution.md#7-实施记录)。

本计划不包含登录注册或后端鉴权。F01–F07 不要求改造数据库或 Worker 协议；F08 所需的后端配置、HTTP 和 Worker 协议增量依据[已确认健康设计](07-health-observation-design.md)独立实施，不修改数据库结构，也不用前端假数据补齐缺失接口。

## 2. 开发顺序与交付点

F 前缀用于前端任务，与后端 P01–P10 分开编号。

| 任务 | 优先级 | 依赖 | 主要产物 | 完成标志 |
| --- | --- | --- | --- | --- |
| F01 工程与基础布局 | 必需 | 本设计 | `web/`、锁文件、Vite、路由、Element Plus、检查脚本 | 类型检查和构建可运行，页面骨架与开发代理可用 |
| F02 API 与客户端生命周期 | 必需 | F01、P01–P10 的接口合同 | HTTP DTO、请求函数、浏览器日志、友好报错、提交请求快照 | 现有接口可调用，业务失败与请求失败分开处理 |
| F03 题目列表与题面 | 必需 | F02 | 列表分页、最新题目、Markdown、语言限额 | 可浏览真实题目，空数据与失败分开展示 |
| F04 编辑器、草稿与提交 | 必需＋首版配套 | F03 | Monaco、语言草稿、UTF-8 预检、幂等创建 | C/Python 可提交并打开结果，原请求可以同键手动重试 |
| F05 提交结果 | 必需 | F02、F04 导航接线 | 详情、轮询、终态分支、固定版本题面 | 状态、诊断与资源显示正确，终态及离页停止查询 |
| F06 提交历史 | 首版配套 | F02、F05 | 后端筛选与分页接入、详情导航、本题提交记录入口 | 可查既有记录并恢复筛选位置，无总条数依赖 |
| F07 浏览器联调与使用说明 | 首版交付 | F03–F06 | 主要路径验证、部署路由示例、运行说明 | UI-01–UI-09 有实际检查记录和明确未测范围 |
| F08 健康观测 | 后续低优先级 | 首版交付、已确认健康设计 | 后端观测接口与对应 GUI、独立过期警告 | H01–H04 的观测合同、页面及过期警告一致，周期获取与手动刷新可用；不计入首版验收门槛 |

F05 完成三个必需页面的业务闭环，F07 完成包括历史与草稿的首版 GUI 交付。F08 可独立排期，不为其预留空页面或首版交付门槛。表中的依赖是能力依赖，不要求人为等待其他不相关功能；例如 F05 的结果渲染可先用契约样例开发，再与 F04 接线。

### 2.1 对运行中后端的要求

“已有后端接口契约”和“后端进程正在运行”是不同的依赖。前端代码编写、类型检查、构建，以及使用契约样例的组件/状态测试可以离线完成；以下真实 HTTP 检查期间才要求后端实际监听并可访问。服务可以在另一个终端前台启动，也可以由已有部署方式在后台运行，不要求特定的进程托管方式。

| 阶段 | 需要运行中后端的部分 | Worker 要求 |
| --- | --- | --- |
| F01 | 仅开发代理连通检查；其余骨架与构建无需后端 | 不需要 |
| F02 | 真实 API 调用、错误响应和创建接线检查 | 只读检查不需要；实际判题时需要 |
| F03 | 读取真实题目列表、题面和语言限额 | 不需要 |
| F04 | 实际创建和重传提交；编辑器、草稿、快捷键可离线检查 | 创建接纳本身不要求 Worker 在线；验证判题完成时需要 |
| F05 | 实际查询提交状态、终态和固定版本题面 | 查询已有记录不需要；观察新任务实际完成时需要 |
| F06 | 真实历史筛选、排序、分页与详情查询 | 不需要 |
| F07 | 真实浏览器主路径必须有运行中后端 | C/Python 判题主路径需要可用 Worker |
| F08 | 后续健康接口的接入与实际状态验证 | 按已确认健康观测契约安排 |

因此 F01–F06 不要求在整个开发期间一直运行后端，但各任务的真实联调完成条件需要启动它；F07 的端到端判题检查必须同时运行后端和 Worker。F08 的接口设计与页面静态开发可离线进行，实际观测检查需要相应服务。后端需使用已初始化并预置题目和测试用户的数据库；已有库重启时不重复执行初始化 SQL，启动时自动继续 queued 并中断旧在途记录。

联调时优先复用已有服务；访问失败时区分网络权限与服务不可用。用户管理的服务由用户收尾，开发任务启动的临时服务由该任务收尾。

## 3. 任务说明

### 3.1 F01：建立前端工程

1. 在 `web/` 建立 Vue 3、TypeScript 和 Vite 工程，接入 Vue Router、Element Plus，创建页面骨架和中文浅色布局；不修改 Cargo workspace。
2. 选择相容的依赖、Node.js 和 pnpm 版本，提交 `pnpm-lock.yaml`，通过 `packageManager` 固定 pnpm 版本，并在 `web/README.md` 记录环境要求。后续安装使用 `pnpm install --frozen-lockfile`。
3. 配置相对 `/api/v1` 请求和 Vite `/api` 代理，代理目标可由开发配置指定；创建 `.env.example`，列出源码上限等实际需要的前端配置。
4. 建立格式、lint、类型、构建及 Vitest 脚本。脚本名称和命令由本任务落实，写入使用说明后成为后续检查依据。
5. 配置路由懒加载，Monaco 在答题页按需加载，明确静态部署的 history 回退规则。

**完成条件：** 页面骨架可启动，类型检查、格式检查、lint 和构建通过，代理能读取现有后端题目 API；没有登录依赖。

### 3.2 F02：统一 HTTP 契约与请求状态

1. 依据[HTTP 契约](03-backend-design.md#5-http-接口)建立题目、分页、创建、历史、提交详情和终态 DTO；终态资源字段保持可选，运行中和 AC 的详情保持 `null`。
2. 用 `fetch` 实现共用请求函数，支持取消和 10 秒超时；统一提取 `error.code`、`message`、可选 `submission_id`，处理网络及非 JSON 响应。
3. 实现题目与提交 API 函数，严格发送允许的请求及筛选字段。创建函数接受调用方提供的 UUID 和冻结快照，不在每次 HTTP 重试时重新生成键。
4. 在内存和 `sessionStorage` 中保存待完成的提交请求快照及幂等键，按设计区分成功、可重试拒绝和明确结束时的保留或清除规则；同一标签页刷新后提示用户手动重试原提交，不自动发送，也不以新草稿替换原请求。提供明确的放弃操作，按设计确认后清除请求快照、保留草稿，再允许开始另一份提交。
5. 建立通用加载、空数据及中文报错提示，说明失败影响和下一步操作；查询参数或页面身份变化时结束旧请求。
6. 建立少量公共浏览器日志函数，记录请求错误、创建结果和状态变化，接入 Vue 与浏览器未捕获异常入口；普通轮询仅输出 debug，日志不包含源码、正文、幂等键或程序输出。

**完成条件：** 核心 API 可与真实后端交互；错误映射保持业务与传输边界，创建响应不明及带 ID 的 `QueueFull` 均保留原快照及键，用户提示可操作且浏览器控制台有必要的错误上下文。

### 3.3 F03：实现题目列表与答题题面

1. 实现包含题号、标题和最新版本号的题目列表，以及无总条数的上一页/下一页；分页参数与 URL 同步，处理整页后的空页。
2. 实现最新题目详情、允许语言与单用例限额，不添加后端未返回的难度、标签、完成率或搜索能力。
3. 建立题面 Vue 组件，用 `markdown-it` 将题面字符串解析为 HTML 并展示，禁用原始 HTML，保留危险链接过滤，覆盖正式示例题的标题和围栏样例。
4. 形成答题页桌面双栏布局，提供“本题提交记录”入口；没有题目或查询失败时不开放无目标提交。不提供题目历史版本列表或切换。

**完成条件：** 实际示例题可浏览，题面与限额清晰，Markdown 原始 HTML 不被执行，空列表和错误能区分。

### 3.4 F04：实现编辑、草稿与创建提交

1. 建立 Monaco Vue 包装，接好 Worker 资源、容器尺寸、C/Python 模式、模型切换和销毁；不引入完整语言服务器。
2. 按题目和语言保存 `localStorage` 草稿，处理恢复、防抖保存、清空确认及存储失败提示；题目版本变化提示一次后更新草稿记录的版本号并保存。添加保存按钮和 Ctrl+S/Cmd+S，阻止保存网页、立即调用共用草稿保存函数，离页时解除监听。
3. 实现语言选择、非空源码与 UTF-8 字节预检；直接发送当前文本，前端上限与部署配置对齐。
4. 点击提交时冻结快照并生成一次 UUID，防止重复点击；正确处理 `202`、`200`、冲突、队列满及响应不明。
5. 收到 `200` / `202` 成功响应后清除请求快照，导航结果页并保留草稿；队列满或响应不明时保留快照，允许原键原内容手动重试。队列满带已有 ID 时提供原记录入口，不自动跳转结果页。

**完成条件：** C/Python 单文件源码可以创建真实提交；草稿切换和刷新后可恢复，响应不明及带 ID 的 `QueueFull` 均能保留原请求并安全重传，不会混入新编辑内容。

### 3.5 F05：实现结果详情与轮询

1. 支持结果 URL 直接访问，读取数据库快照，展示身份、实际固定版本和时间；按固定版本接口获取可折叠题面。
2. 提交处于排队中、分派中或判题中时，每次详情请求完成后等待 1 秒再查询同一接口，不重叠请求；终态、离页、提交 ID 变化和标签页隐藏时停止，重新可见时仅对尚未终态且未因查询失败暂停的提交查询最新快照。
3. 分别渲染 AC、CE、用例失败和执行失败。实现 Base64 字节解码、UTF-8 文本展示、截断提示，以及可选资源和退出信息。
4. 请求失败保留最近成功状态并提示过期，暂停等待手动重试，切换标签页不会自动恢复；不根据等待时长判定 TLE 或失败。查询到后端已持久化的 `failed / SchedulerInterrupted` 时展示重启中断原因并停止轮询，不自动新建提交。
5. 接通返回答题和本题提交记录，明确草稿与历史提交源码的区别；版本题面加载失败不遮蔽已取得的结果。

**完成条件：** UI-03/UI-04 主要分支有验证，终态和离页无残留轮询；从题目列表进入答题页，创建真实提交后可导航至结果页并查看终态。

### 3.6 F06：实现提交历史

1. 实现题号、状态、verdict 筛选和上一页/下一页；查询参数传给后端，由后端筛选、按既定创建时间/ID 倒序排列再分页，前端展示返回顺序；筛选与分页写入 URL，修改筛选重置 offset。
2. 直接使用历史摘要字段，不逐行请求详情或题目，提供手动刷新和清除筛选。
3. 每条记录进入同一个结果页，在结果 URL 中保留历史筛选和生效分页参数，刷新后仍能返回原查询位置；独立结果链接返回历史首页。答题与结果页面的“本题提交记录”入口携带 `problem_id`，只在提交记录中查看该次提交的固定版本。
4. 处理暂无提交、筛选无结果、空分页和查询错误，说明当前为后端配置用户的历史。

**完成条件：** 历史筛选、分页、前进后退和详情导航可用，结果不依赖当前浏览器是否创建过该提交。

### 3.7 F07：完成首版联调与操作说明

1. 按第 4 节执行前端检查及少量有针对性的测试，复用 P10 已有的 C/Python AC、C CE、Python WA、C TLE 源码样例，完成浏览器主路径。
2. 使用当前后端的启动步骤，记录接口、开发代理、构建产物、静态部署、history 回退、HTTPS/localhost 和前端源码上限配置要求。
3. 检查直接结果链接、刷新、前进后退、桌面布局、草稿恢复与 Ctrl+S、浏览器日志和友好报错，以及健康接口缺席时核心功能可正常使用。
4. 在[实施记录](d02-execution/06-frontend-development-execution.md#5-实施记录)登记实际检查、命令、范围与剩余限制；更新根说明中的 GUI 入口，保持后端进度记录原样准确。

**完成条件：** 新操作者可以按说明启动已有 Worker/后端与前端，浏览题目并完成一次实际判题；UI-01–UI-09 的检查有记录，未执行范围如实列出。

#### 3.7.1 验收范围

验收覆盖 C/Python AC、C CE、Python WA 和 C TLE 的浏览器流程，以及幂等重试、轮询、结果展示、历史、草稿、快捷键、桌面访问、报错和日志。复用 F01–F06 对应的检查记录，仅补查未覆盖或发生改动的分支；实际结果见[浏览器联调实施记录](d02-execution/06-frontend-development-execution.md#57-f07首版浏览器联调与操作说明)。

后端 P01–P10 不因 F07 重新开放，不扩展为 F07 的 Worker 改造或完整 Rust 测试任务。

#### 3.7.2 执行顺序与产物

1. **整理验收范围。** 按 UI-01–UI-09 核对[实施记录](d02-execution/06-frontend-development-execution.md#5-实施记录)和 P08–P10 的实际检查，区分真实服务、受控响应和单元测试，仅补查未覆盖或发生改动的条目。
2. **确认联调条件并执行前端检查。** 优先读取已有后端的题目和历史接口，按第 2.1 节区分网络权限问题与服务不可用；真实新任务需要可用 Worker。复用现有 Node.js/pnpm、锁文件和浏览器工具，执行第 4.1 节检查命令，不默认新增依赖或端到端测试框架。保留用户管理的后端和 Worker，只收尾本任务启动的临时服务。
3. **补齐真实浏览器主路径。** 选定一个桌面浏览器，在 1440×900 视口从题目列表进入正式示例题，使用 `time-limit.c` 提交，核对 API 与页面均为 `finished / TLE`、首个失败用例为 1，终态后无继续轮询。继续检查本题历史、结果直接链接/刷新、返回历史与答题、草稿保存及语言切换。AC/CE/WA 优先复用已有真实提交，仅在记录不足或行为改动时新建必要任务。
4. **核对最终构建与访问说明。** 使用构建产物在 1024×900 桌面检查关键页面和编辑器资源，确认直接结果链接与刷新可用。核对静态服务规则：页面路径回退到 `index.html`，API 保留后端响应，不存在的静态资源返回 404，Monaco Worker 使用同源资源。记录实际使用的服务；仅使用 Vite preview 时，不将其记作 Nginx 部署或 HTTPS 验收。核对 localhost/HTTPS、源码字节上限与后端配置对齐的说明。
5. **修复具体问题并收口文档。** 若发现缺陷，只修改相关实现并运行对应检查；新增回归测试须对应具体失败或要求。将实际命令、浏览器/视口、检查结果及未测范围登记在[实施记录](d02-execution/06-frontend-development-execution.md#5-实施记录)，补充 UI 验收对应关系，并同步根说明、前端说明和受影响的设计合同。纯文档或前端工作不重复 Rust/Isolate 专项验收。

#### 3.7.3 完成判断与后续顺序

- 五条真实判题路线都有浏览器检查记录，其中新增 TLE 必须取得真实后端和 Worker 的结果，不能以受控响应替代。
- UI-01–UI-09 均有实际检查结果，标明复用与新增检查；发现的首版范围内问题已修复并完成对应验证，必要条目未完成时保持 F07 未完成。
- 新操作者可按根说明和前端说明完成启动、浏览、编辑、提交与结果查询；部署示例和实际执行范围清楚区分。
- F07 完成后按[已确认健康设计](07-health-observation-design.md)进入 F08，依次实施 H01–H03 后端观测和 H04 GUI。登录、多用户隔离、历史源码查询和移动端不纳入本轮。

### 3.8 F08：后续健康观测

1. 核心交付后，按已确认设计实施后端观测来源、状态 RPC、共享探测和 HTTP 快照。当前 Scheduler 缓存不能直接作为实时健康保证。
2. 按健康设计的 H01–H03 实现并验证后端，再通过 H04 接入只展示指标的 `/health` 页面、每 10 秒自动获取及手动刷新。
3. 使用已确认的派生阈值判定观测过期，页面提供独立警告区，列出过期对象及检查时间。接口缺失时如实记录实现尚未完成，不用成功读取题目冒充整体健康。

**完成条件：** 观测契约、后端实现、GUI、独立过期警告和相关文档一致。外部告警、自动修复、服务重启及通用监控平台不由本任务自动扩展。

具体方案与验收要求见[健康观测设计与实施计划](07-health-observation-design.md)，范围确认见[审核记录](d01-review/07-health-observation-review.md)，实际检查见[健康观测实施记录](d02-execution/06-frontend-development-execution.md#58-f08h01worker-状态-rpc)。

## 4. 验证与交付要求

### 4.1 自动检查与契约测试

检查脚本由 `web/package.json` 定义。前端变更在 `web/` 执行 `pnpm format:check`、`pnpm lint`、`pnpm typecheck`、`pnpm build`，以及与改动相关的 `pnpm test`；安装使用 `pnpm install --frozen-lockfile`。具体环境与命令见[前端说明](../web/README.md#检查命令)。纯前端改动不要求重复运行 Rust/沙箱测试；若未来修改 Rust，仍执行仓库要求的格式、编译、Clippy 和相关测试。

用 Vitest 和必要的 Vue 组件测试工具验证以下实际契约，按模块合并用例，不为静态页面写重复测试：

- 幂等创建：响应不明后的同键同内容、编辑后仍保留原快照、成功响应后清除快照；带 ID 的 QueueFull 保留快照且不自动跳转，刷新后仍可原键原内容手动重试；明确业务拒绝结束或确认放弃后清除快照、保留草稿并允许新的主动提交。
- 轮询生命周期：非终态继续、终态停止、离页/换 ID/隐藏页清理，查询错误与业务 `failed` 分离，错误后切回标签页仍等待手动重试。
- 结果转换：AC/CE/用例失败/执行失败、Base64 与截断、可选统计和显式零值、资源单位。
- 本地草稿：题目与语言隔离、刷新恢复、成功提交保留，版本变化提示并成功保存后不重复提示，存储失败不显示已保存。
- 保存快捷键：Ctrl+S 阻止保存网页，立即保存当前语言草稿且不创建提交，离页后解除监听。
- 报错与日志：请求失败有可操作的中文提示及控制台上下文，普通轮询不刷 info，日志不输出正文或幂等键。

接口样例来自现有 HTTP DTO 和设计，受控返回只证明前端行为。可用浏览器网络拦截或轻量假响应覆盖不易稳定制造的界面分支，不搭建第二个模拟判题平台，不要求真实构造全部故障和 verdict。

### 4.2 真实浏览器主路径

复用[本地启动说明](../README_zh-CN.md#quick-start)、正式两数求和题和 `examples/submissions/` 五份源码。少量实际任务检查浏览器 → HTTP → Scheduler → Worker → MySQL → 结果页：

| 路线 | 检查内容 |
| --- | --- |
| C AC（`a-plus-b.c`） | 列表进入题目、编辑提交、查询到 AC、终态后停止轮询 |
| Python AC（`a-plus-b.py`） | 语言切换、草稿隔离、提交到结果、刷新恢复和历史入口 |
| C CE（`compile-error.c`） | 编译诊断可读、截断状态与 API 一致，不展示失败用例 |
| 首个用例 WA（`wrong-answer.py`） | 失败用例序号、输出与可用统计符合实际详情，不出现后续用例或答案 |
| C TLE（`time-limit.c`） | 展示 `finished / TLE` 和首个失败用例，不误记为基础设施执行失败 |
| 界面与访问 | 后端分页/筛选、草稿刷新与 Ctrl+S、中文报错与控制台日志、直接结果链接、前进后退、代理和桌面布局 |

选定一个桌面浏览器，在宽度不小于 1024 CSS px 的视口运行真实主路径并记录浏览器和视口；不安排移动端、手机竖屏或更窄视口检查。另一个桌面浏览器仅在需要验证兼容性或发现具体问题时补查。首版可手动执行并登记结果；若后续需要重复执行同一用户链路，再引入对应浏览器自动化，不预设全浏览器矩阵或大规模端到端测试框架。

同键重传只有一条提交的后端行为，以及 queued 启动装入、旧在途中断、正常停机和故障退出，可复用 P08–P10 已有测试与验收结果；GUI 另行检查重试入口、键保持和对应错误展示，受控 HTTP 响应仅验证前端分支。双 Worker 忙时立即换节点及不同提交同时执行按 P10 验收，F07 复用其对应记录。后端重启、故障停机、其余失败 verdict、完整沙箱隔离和健康观测不属于本次新增的真实浏览器矩阵。

### 4.3 交付要求

- F01–F07 的完成条件及[GUI 验收标识](05-frontend-design.md#7-首版验收)有对应的实际检查记录。
