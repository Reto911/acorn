独立的 Vue 3 + TypeScript 浏览器工程。当前完成 F01–F07：中文浅色页面、路由懒加载、本地 Monaco 和编辑器 Worker，HTTP 客户端与提交请求恢复/重试/放弃入口，真实题目浏览，C/Python 编辑、本地草稿、主动提交，结果详情、固定版本题面和状态轮询，以及历史筛选、分页和详情往返。首版桌面浏览器联调已完成，五条真实判题路线、UI-01–UI-09 对应关系和实际检查范围见[联调记录](../docs/06-frontend-development-plan.md#57-f07首版浏览器联调与操作说明)。F08 / H04 已完成 `/health` 系统状态页面、每 10 秒自动获取、手动刷新及独立过期警告，自动获取改进见[最新记录](../docs/06-frontend-development-plan.md#512-健康页面每十秒自动获取)，初次实际连通检查保留在此前章节。

设计和任务依据见[前端 GUI 设计](../docs/05-frontend-design.md)和[前端开发计划](../docs/06-frontend-development-plan.md)。

LLM 审查结果区、手动启动及重跑、finished/PENDING 继续轮询和 review_status 历史筛选均已批准、待实施，见[LLM 设计](../docs/08-llm-code-review-design.md#8-http-与前端增量)。下述操作和检查记录描述当前基础 GUI；终态停止轮询及五个历史参数是现有实现，L05 将按同步后的 GUI 设计扩展，不表示当前已支持审查。

GUI 仅面向桌面浏览器，支持与验收视口宽度不小于 1024 CSS px。移动端及更窄视口不在适配、测试或交付范围，无需检查手机竖屏效果；已有窄屏样式不构成支持承诺或后续维护要求。

## 环境与安装

- Node.js：24.x，至少 24.21.0；本任务使用 24.21.0，`.nvmrc` 固定该版本。
- pnpm：12.11.2，`package.json` 的 `packageManager` 固定版本。
- Vue 3.5.43、Vue Router 4.6.4、Element Plus 2.14.7、Monaco 0.57.0、markdown-it 15.0.2、Vite 8.3.4、TypeScript 6.0.3、Vitest 5.0.4；完整依赖版本见 `package.json` 和 `pnpm-lock.yaml`。

在本目录执行：

```sh
nvm use
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env.local
pnpm dev
```

`nvm use` 仅适用于使用 nvm 的环境；其他安装方式也可提供上述 Node.js 版本。若已有 pnpm 12.11.2，无需重复启用 Corepack。项目只维护 pnpm 锁文件，不混用 npm/yarn 安装。

开发地址为 `http://localhost:5173`，默认只监听本机 `127.0.0.1`。端口占用时明确退出，不自动改用其他端口。开发期间按[后端启动说明](../README.md#程序入口)启动后端，使用已初始化并预置测试用户和题目的数据库；F01 只读代理检查无需 Worker。不要重复初始化已有数据库。

## 配置与 API 代理

| 变量                    | 默认值                  | 用途                                      |
| ----------------------- | ----------------------- | ----------------------------------------- |
| `API_PROXY_TARGET`      | `http://127.0.0.1:8080` | Vite 服务端读取的后端地址，不注入浏览器   |
| `VITE_SOURCE_MAX_BYTES` | `65536`                 | 浏览器源码 UTF-8 字节上限；主动提交前预检 |

在 `.env.local` 修改开发配置后重启 Vite。前端 HTTP 客户端统一使用相对 `/api/v1` 路径，不直接写后端主机地址。代理将 `/api` 原样转发，因此 `/api/v1/problems` 在后端仍为 `/api/v1/problems`，无需后端新增 CORS。

后端运行时，在另一终端检查代理：

```sh
curl --fail-with-body http://localhost:5173/api/v1/problems
```

应取得真实后端的 `items`、`limit`、`offset` 分页 JSON。打开 `/problems` 可浏览真实题目，再点击标题读取题面和语言限额；这些只读功能不需要 Worker。题目 API 可访问不代表 Worker 健康。

`VITE_` 变量属于公开构建配置，不能放入秘密。源码上限需与后端 `[request].source_max_bytes` 对齐；生产配置必须在构建时提供，部署后修改 `.env.local` 不会改变已有产物。后端始终执行最终校验。

## 健康观测

从主导航点击“系统状态”，或直接打开 [本地健康页面](http://localhost:5173/health)。页面进入时立即请求 `GET /api/v1/health`，此后在页面挂载期间每 10 秒自动获取一次，也可以点击“刷新状态”。两种获取都只读取后端本地状态和观测缓存，不立即触发数据库或 Worker 探测。定时到达时若请求尚未结束则跳过该轮；请求失败后下一轮继续获取，成功后清除错误。离开页面后清理定时器并取消在途等待，其他页面的查询策略保持原样。

页面展示“获取时快照”及后端组装时间，并分别显示新提交接纳条件、Scheduler 生命周期和待接纳名额、数据库读取状态，以及各 Worker 的检查结果、执行状态、停机标记、未确认结果数量和容量。各项最后检查时间独立显示，时间按浏览器时区格式化；尚无结果时显示“尚未检查”。数据库“读取正常”只表示该次读取检查完成，Worker “检查成功”只表示取得有效状态，均不保证下一次提交或判题成功。

数据库或 Worker 返回 `stale` 时，指标区域上方的独立警告区列出过期对象及其最后检查时间；自动获取或手动刷新取得新状态后逐项移除，全部恢复后隐藏。过期只依据后端状态，不在浏览器增加过期计时器。默认后端过期阈值为 12 秒，具体规则见[健康设计](../docs/07-health-observation-design.md#44-缓存状态和错误码)。

`unknown`、`failed`、`stale` 分别显示尚未取得结果、检查失败和观测已过期，检查失败附中文说明和稳定错误码。队列满、Worker 执行中、结果区满和停机标记分别展示，不合成整体健康或可接纳结论，也不禁用答题提交按钮。HTTP 首次请求失败提供重试并继续定时获取；刷新失败保留上次快照并标注旧数据，请求错误与观测过期警告分别显示。

初次检查覆盖构建产物的桌面页面、受控过期与请求错误分支，以及同版空闲 Worker 停止和恢复后的手动刷新，见[健康交付记录](../docs/06-frontend-development-plan.md#511-f08h04健康页面与最终连通验收)。后续每 10 秒自动获取的实现、既有受控浏览器证据及其版本对应限制见[补充记录](../docs/06-frontend-development-plan.md#512-健康页面每十秒自动获取)；当前版本的周期获取尚缺可追溯的验收记录。

## 首次完整判题

1. 按[后端启动说明](../README.md#程序入口)准备题目和配置，启动 Worker 与后端；已有库不重复初始化。实际取得新任务的判题结果需要可用 Worker。
2. 完成本页的环境安装和本地配置后运行 `pnpm dev`，打开 [题目列表](http://localhost:5173/problems)，进入“两数求和（A + B）”，确认题面、版本和语言限额已加载。
3. 选择 C 或 Python 3，将 [C AC 源码](../examples/submissions/a-plus-b.c)或 [Python AC 源码](../examples/submissions/a-plus-b.py)粘贴到编辑区。Ctrl+S/Cmd+S 保存本地草稿，切换语言不会覆盖另一语言的草稿。
4. 点击“提交代码”，创建成功后自动进入结果页。等待 AC，展开“判题版本题面”查看该次固定版本；刷新结果链接仍可查询持久化结果。
5. 点击“本题提交记录”查看历史，进入记录后可返回原筛选和分页；“返回答题”恢复本地草稿，不代表读取了历史提交源码。

其他正式样例及预期结果见[源码样例说明](../README.md#从源码文件提交并核对结果)。CE、WA、TLE 都是状态为 `finished` 的正常判题结论；`failed` 和 HTTP 请求失败分别展示执行故障与当前请求错误。

## 题目浏览与题面

`/problems` 显示题号、标题和最新版本，使用后端分页，不依赖总条数。直接进入时省略未指定的分页参数，采用后端默认值；上一页/下一页将生效的 `limit` 和目标 `offset` 写入 URL，刷新和前进后退可恢复位置。恰好整页后的空页保留上一页入口，空题库与请求失败分别提示。刷新失败保留最近成功数据并标明可能过期，用户可手动重试。

`/problems/:problemId` 读取最新题面，展示当前版本和接口返回的允许语言及单用例 CPU、墙钟、内存限额，时间显示 ms，内存由 KiB 换算为 MiB。题面由 `ProblemStatement.vue` 使用 markdown-it 解析，禁用原始 HTML，保留默认危险链接过滤，不编译其中的 Vue 表达式。桌面采用双栏布局，题面区可独立滚动。题目不存在或首次读取失败时不显示编辑区。

“本题提交记录”入口携带 `problem_id`，进入该题的历史首页。语言选择来自题目允许语言，并同步显示对应限额；新建提交由后端在创建时选择最新版本，页面展示版本不锁定执行版本。题面刷新期间及刷新失败后禁止主动新建，待完成原请求仍可独立重试。

## 编辑、草稿与提交

编辑器支持 C（Monaco 的 `cpp` 模式）与 Python 3，不接入语言服务器。空草稿从空编辑区开始，各语言使用独立模型，离开答题页销毁模型和编辑器。提交前检查源码非空以及 `TextEncoder` 计算的 UTF-8 字节数，不裁剪、去空白或改写当前文本；空白文本仍交由后端判断。

草稿由 `useDraft` 管理，存入 `localStorage` 的 `acorn:draft:v1:<problem_id>:<language_id>`，字段为 `source`、`version_no`、`updated_at_ms`；`acorn:draft-language:v1:<problem_id>` 记录最后选择的语言。输入后约 1000 ms 防抖保存，切换语言、题目、离页和刷新前补存；恢复时只选择当前仍允许的语言。题面版本改变保留代码、提示复核，并立即保存新的展示版本；保存成功后再次打开同一版本不重复提示。

“保存草稿”和 Ctrl+S/Cmd+S 使用同一保存入口，快捷键阻止保存网页、只保存一次且不创建提交，离页解除监听。“清空本语言草稿”确认后只删除当前题目和语言的草稿。存储不可用或写入失败时保留当前页面内存内容、明确提示未保存，仍可编辑和提交。草稿不跨标签页自动合并，不作为备份。

“提交代码”冻结点击时的题号、语言与源码，待完成请求存在时禁止另建请求，编辑与切换语言仍可继续。`200` / `202` 成功后跳转结果页并保留草稿，离页或更换题目后不迟到跳转；结果页随后独立读取后端快照。

## 提交结果

`/submissions/:submissionId` 支持直接打开和刷新，显示完整提交 ID、题号、实际判题版本、语言、创建与终态保存时间。日期使用中文格式和浏览器本地时区，并标明时区；提交总耗时包含排队和调度，不是程序运行耗时。“返回答题”打开最新题面与本地草稿，草稿不代表该次历史提交源码；“本题提交记录”携带题号进入历史首页。

`useSubmissionPolling` 进入页面立即查询详情，`queued` / `dispatching` / `running` 时在上一请求完成后等待 1 秒再查询，不重叠请求。`finished` / `failed` 停止轮询；离页、ID 改变和标签页隐藏时清理定时器与在途请求，忽略迟到响应。重新可见时仅对未终态且未因查询失败暂停的提交立即查询。GET 失败保留最近快照、标明过期并暂停，切换标签页不能解除暂停，需手动重试；“刷新结果”也可手动读取当前快照。等待时长不会被推断为 TLE 或失败。

`SubmissionOutcome.vue` 分别展示 AC、CE、用例失败和执行失败。编译诊断、stdout/stderr 由 `OutputText.vue` 先解码 Base64 字节，再按 UTF-8 显示；非法 UTF-8 使用替换字符，内容作为可滚动、可选中复制的纯文本呈现，服务端截断标记单独提示。用例失败只展示首个失败用例，其资源从微秒/字节换算为 ms/MiB；缺失值与显式 0 分开显示。AC 不增加逐点结果或资源总计，`failed / SchedulerInterrupted` 说明重启中断并停止，不自动重新提交。

`FixedProblemStatement.vue` 按提交固定的题号和版本调用显式版本接口，折叠展示对应标题、Markdown 题面及该次语言限额；不会读取最新题面替代历史版本。题面查询独立于结果轮询，不随每次快照重复请求；题面失败时标明未加载并提供独立重试，已取得的判题结果仍可查看。

## 提交历史

`/submissions` 读取后端配置用户的持久化历史，包括当前浏览器没有创建过的记录。题号、状态和判题结论在点击“查询”后应用，筛选由后端执行；状态与结论同时设置时取交集。清除筛选同时清除尚未应用的表单内容。应用或清除筛选将 offset 归零并保留生效页长；URL 仅使用 `problem_id`、`state`、`verdict`、`limit`、`offset`，直接访问、刷新和前进后退均可恢复。

表格只使用历史摘要，显示完整提交 ID、题号、固定版本、语言、状态、结论及创建/终态时间，按后端返回顺序展示。没有结论或终态时间时明确显示未产生；时间与结果页使用相同的中文格式和浏览器时区。列表不逐行读取题目或详情，不自动刷新；首次采用后端默认页长，上一页/下一页使用生效值，无总条数和任意页跳转。恰好整页后的空页仍可返回上一页，回到首页保留筛选，手动刷新当前页。新记录插入可能使 offset 分页重复或跳过记录，需回到首页并刷新查看最新提交。

历史行的结果链接携带当前筛选与生效分页参数，结果页刷新后“返回提交历史”仍恢复原位置；独立结果链接没有这些参数时返回全部历史首页，不保存额外的浏览器历史业务状态。暂无记录、筛选无结果、空分页和查询失败分别提示。刷新失败保留最近成功列表并标明可能过期，等待手动重试；查询条件变化时清除旧列表、取消旧请求并忽略迟到响应。错误提示另提供全部历史首页入口，以重置无效的 URL 查询参数。

## HTTP 与待完成的提交请求

`src/api/types.ts` 对应后端 HTTP JSON，`src/api/index.ts` 提供题目列表、最新/固定版本题面、创建、详情和历史调用。请求使用 10 秒超时和可选 `AbortSignal`，HTTP 错误、网络、超时、取消及无法解析响应由 `RequestError` 区分，业务 `failed` 仍是成功取得的提交详情。`useQuery` 接受页面身份/查询参数 getter，在变化和离页时取消并忽略旧响应；`reload()` 保留最近成功数据，供页面显示过期提示和手动重试。

主动提交使用 `useSubmissionRequest().start(body)`：它生成一次 UUID，复制并冻结 `problem_id`、`language_id`、`source`，在发送前写入当前标签页 `sessionStorage`。待完成请求存在时不允许开始另一份请求；`retry()` 只重传原快照和原键，不读取编辑器或草稿。成功和明确业务拒绝清除快照，队列满（包括已有 ID）、后端停止接纳和响应不明时保留。底层 `createSubmission(requestKey, snapshot)` 不生成新键、不自动重试。

答题页提供待完成请求的恢复提示、手动重试和确认放弃。刷新不自动 POST；队列满带 ID 时提供记录链接，成功重试才导航结果页。请求在途不能放弃，确认放弃不会撤销后端提交，也不会清空草稿。会话存储不可用时明确提示本次请求只能在内存中保留，刷新可能失去原请求的恢复入口。请求快照和长期草稿独立保存，后续编辑、清空草稿均不会替换原请求。

`RequestFeedback.vue` 提供加载、空数据、可操作中文报错与手动重试。公共日志只在浏览器控制台输出请求元数据、创建结果、状态变化及异常类型/调用栈帧，不输出源码、请求正文、幂等键或程序输出；生产默认关闭 debug。未捕获异常另显示页面提示，不把 HTTP 错误当作判题终态，也不据此宣称 Worker 健康。

| `/submissions/:submissionId` | 提交结果         |

`src/router.ts` 使用 HTML5 history，页面均通过动态导入加载。Element Plus 组件和对应样式在使用处显式导入，中文 locale 由根组件提供，不进行全量组件注册。答题页再异步加载 `CodeEditor.vue`，其中引入 Monaco 的 ESM 编辑器、C/Python 模式与 `?worker` 资源；题目列表、提交历史和结果页不会加载 Monaco。资源来自本地构建产物，不依赖运行时 CDN。

## 构建与静态部署

```sh
pnpm build
pnpm preview --host 127.0.0.1 --port 4173
```

`preview` 仅用于本地预览构建产物。实际部署由静态服务器提供 `dist/`，同源 `/api/` 反向代理到 Axum；后端仍只提供 API。当前工程按域名根路径部署。

Nginx 路由示例（路径和监听地址按实际部署修改）：

```nginx
server {
    listen 80;
    server_name localhost;
    root /srv/acorn/web/dist;
    index index.html;

    location = /api {
        proxy_pass http://127.0.0.1:8080;
    }

    location ^~ /api/ {
        proxy_pass http://127.0.0.1:8080;
    }

    location ^~ /assets/ {
        try_files $uri =404;
    }

    location ~ \.[^/]+$ {
        try_files $uri =404;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

页面路径如 `/submissions/<id>` 必须回退到 `index.html`，才能直接打开和刷新。API 错误由后端返回，不回退成 HTML；不存在的静态资源返回 404。Monaco Worker 必须作为同源构建资源提供。

F07 使用临时本机静态服务提供 `dist/` 并代理真实后端，检查了上述路由规则、1024×900 桌面布局和 Monaco Worker；没有执行 Nginx 或 HTTPS/TLS 部署。临时服务与浏览器脚本只用于本次验收，不是工程依赖，实际证据见[联调记录](../docs/06-frontend-development-plan.md#57-f07首版浏览器联调与操作说明)。

创建提交使用 `crypto.randomUUID()`：本地开发使用 localhost，远程部署配置 HTTPS。上述 HTTP 示例仅说明静态文件与 API 路由，不包含 TLS 配置。当前没有登录；健康页面沿用同源 API 和现有部署访问边界。
